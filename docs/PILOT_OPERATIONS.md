# 付费试点执行清单

这份清单用于前三个创始试点。它是操作约定模板，不替代适用法律、税务要求或双方另行签署的合同。

## 当前交易条件

- 服务提供方式：个人提供有明确范围的 RabbitMQ 诊断服务。
- 价格：人民币 1,999 元 / 14 个自然日 / 1 个集群，开始前付款。
- 收款：微信或支付宝个人收款，只在私聊中发送付款方式。
- 开票：当前不提供发票，不接受对公付款。付款平台交易记录不是发票。
- 不匹配客户：必须对公付款、必须取得发票，或要求 24/7 支持、生产代操作、事故赔付及可用性担保的团队。

收款前，服务方需要自行确认所用微信或支付宝账户允许当前交易，并遵守所在地、支付平台和税务要求。如果无法确认，暂停收款。不得虚构或借用开票主体。

## 从公开申请转到私有仓库

1. 申请人提交公开 GitHub Issue，只填写客户画像、问题类别、接入条件和商业要求。
2. 检查 Issue 中没有公司名称、联系方式、内部标识、日志、快照、交付包、付款信息或凭据；发现后立即要求申请人编辑删除，不要引用或复制这些内容。
3. 从私有模板为这位申请人创建一个独立私有仓库。仓库名只使用公开 Issue 编号，不使用客户名称：

   ```bash
   gh repo create fly1d/rabbitmq-guard-pilot-<issue-number> \
     --private \
     --template fly1d/rabbitmq-guard-pilot-template
   gh api repos/fly1d/rabbitmq-guard-pilot-<issue-number> \
     --method PATCH \
     -F has_issues=true \
     -F has_wiki=false \
     -F has_projects=false >/dev/null
   gh api repos/fly1d/rabbitmq-guard-pilot-<issue-number> --jq .visibility
   ```

4. 从公开 Issue 读取作者用户名，只有上一步返回 `private` 后，才以只读协作者权限邀请该账号：

   ```bash
   applicant=$(gh issue view <issue-number> --repo fly1d/rabbitmq-guard --json author --jq .author.login)
   gh api \
     --method PUT \
     repos/fly1d/rabbitmq-guard-pilot-<issue-number>/collaborators/"$applicant" \
     -f permission=pull
   gh api repos/fly1d/rabbitmq-guard-pilot-<issue-number>/invitations \
     --jq '.[] | {login: .invitee.login, permissions}'
   ```

   再次核对待接受邀请只有预期申请人，且权限是只读。不得邀请公司机器人账号或无关人员，也不得给予 `push`、`maintain` 或 `admin` 权限。
5. 申请人接受邀请后，检查除所有者外的协作者只有预期申请人，再让其使用“试点启动确认”Issue Form：

   ```bash
   gh api repos/fly1d/rabbitmq-guard-pilot-<issue-number>/collaborators \
     --jq '[.[] | select(.login != "fly1d") | {login, permissions}]'
   ```

   双方只确认条款和交换微信，不上传日志、快照、交付包、付款信息或凭据。
6. 在公开 Issue 只回复“已发送独立私有仓库邀请”；不要粘贴私有仓库地址、微信号、邮箱或聊天截图。
7. 不得让两个客户共用一个私有仓库。试点结束并完成数据删除后，先移除客户协作者，再归档私有仓库；删除仓库需要另行确认。

支付宝只用于收款，不作为客户支持渠道。私有 GitHub Issue 用于启动确认，微信用于进度协调和复盘安排。脱敏 ZIP 通过客户批准的私密文件渠道发送，并通过另一个已确认渠道核对 SHA-256。

## 付款前书面确认

在微信私聊中补全以下模板。双方都明确回复“同意以上约定”后，服务方才能发送付款码或支付宝收款信息。

```text
RabbitMQ Guard 14 天创始试点确认

公开申请：GitHub Issue #____
服务方真实姓名及收款页面显示姓名：____
客户联系人：____（仅私下记录）
服务集群：1 个，以交付包中的同一伪名集群为准
固定版本：RabbitMQ Guard v____
费用：人民币 1,999 元
付款方式：微信个人收款 / 支付宝个人收款
发票：本次不提供发票，付款平台交易记录不是发票
开始日期：____年__月__日
结束日期：____年__月__日（共 14 个自然日）

交付：
1. 一次脱敏基线交付包审查
2. 一份证据与风险优先级报告
3. 一次 60 分钟技术复盘和整改建议
```

不要在付款备注中填写公司名、集群名、故障描述或其他客户信息。只使用 `RG-<GitHub Issue 编号>`。客户核对私聊中预先确认的收款显示姓名后再付款；无需在 GitHub 上传付款截图。

## 交付与结束

1. 到账后私下记录金额、平台、时间和平台交易号；不把记录提交到仓库。
2. 客户发送脱敏 ZIP 后，先运行 `verify-delivery`。校验失败时停止分析，请客户在本机重新生成。
3. 报告和复测严格按付款前确认的范围交付，不在试点中临时承诺值班或生产变更。
4. 结束时确认交付完成、是否愿意续费及真实原因；不要只记录“满意”。
5. 在约定删除日删除脱敏交付包和派生报告，并在微信中确认完成。保留范围确认和必要交易记录时，不得包含客户诊断数据。
6. 在内部商业记录中只统计匿名结果：是否付款、是否要求发票、是否完成交付、是否愿意续费及主要原因。不得把客户身份或资料提交到公开仓库。

## 开票能力触发条件

当前不为了尚未验证的需求先虚构主体。如果一位符合客户画像、愿意按 1,999 元付款的客户明确只因发票或对公付款无法成交，记录一次“开票阻断”。出现真实阻断后，再由服务方使用本人真实身份咨询所在地税务机关或办理合规经营主体；这一步需要本人实名、地址、税务和银行信息，不能由仓库自动完成。
